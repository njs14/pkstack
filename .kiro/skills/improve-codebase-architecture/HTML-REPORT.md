# Architecture survey report

Use the inspected module and domain names. Each candidate needs a before/after visual, affected
files, observed friction, proposed change, dependency strategy, caller/test benefits, risk, and
recommendation strength. Mark proposed structure as proposed and link the supporting source.

Use show-me for compact inline diagrams or the installed Archify renderer for a polished artifact.
Do not fetch CDN libraries or execute remote renderers. In native Plan, keep the report in
conversation; when writing is permitted, use a fresh local temporary path unless requested otherwise.

Choose a dependency graph for coupling, a sequence for repeated round trips, or a small SVG showing
which responsibilities move behind the interface. Label arrows and give text equivalents. Keep
before and after scales comparable; use color as a supplement to labels. End with one recommended
candidate and why it earns attention now. Inspect the rendered artifact for clipped labels and
incorrect relationships before sharing its path. A diagram communicates the proposal; it does not
prove runtime behavior or authorize a refactor.
