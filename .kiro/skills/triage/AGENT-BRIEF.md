# Prepare an actionable brief

The brief carries verified context into Kiro's native planning workflow. It is not a replacement
Spec, task graph, or automatic execution grant. Write a local draft unless posting is explicitly
authorized. Preserve prior settled answers when resuming.

Include category and recommendation; current versus desired behavior; issue/PR and exact candidate
identity; reproduction command and observed result or why verification is unavailable; relevant
interfaces and source pointers; independently testable acceptance criteria; scope limits; and
unresolved information with the person or evidence source that can answer it. For a PR, explain
what remains to be done to the attached diff rather than describing a fresh implementation.

Describe durable behavior and domain concepts. Cite paths and lines as evidence at the inspected
revision, not timeless implementation instructions. Link an existing native Spec and identify the
proposed delta. For needs-info, separate established facts from specific unanswered questions.
For human-only work, state which access or judgment prevents agent execution. Readiness remains
conditional on those facts and the user's actual authority; a label is not executable proof.
