# Reflection lenses and synthesis

The three reviewers inspect the same bounded current-session evidence. They are
independent and read-only. They do not inspect private transcript stores or
unrelated conversations, and they do not edit files or external systems.

## Judgment lens

Find the durable decision rule behind a concrete mistake, correction, useful
choice, or repeated manual step. Preserve the user's demonstrated preference
only when the evidence supports it. Route a missed skill activation to its
description rather than adding buried body text.

## Tooling lens

Find the command, option, path convention, isolation method, or artifact check
that a future run would otherwise rediscover. Prefer a generator, test, lint,
or runtime check when it can enforce the fact. Flag context that an in-scope
read-only tool could have retrieved instead of asking the user to repeat it.

## Divergent lens

Look beneath the obvious lesson. Test second-order effects, skipped consumers,
verification that passed by luck, negative evidence, and an alternative path
that would change the decision. Do not invent work for a skill that was neither
used nor a credible missed trigger.

## Candidate format

Each reviewer returns three to five rows:

- principle;
- exact supporting event or artifact;
- proposed target and section;
- failure prevented; and
- whether a structural mechanism is a better home.

## Synthesis

Spot-check evidence before accepting a row. Merge duplicates and preserve
meaningful disagreement. Accept only durable, specific, decision-changing
lessons with a real owner. Reject vague, version-bound, duplicate, unsupported,
or out-of-scope lessons. Put a valid idea in Backlog when a structural mechanism
needs design beyond this reflection.

Present all three buckets before action. No edit, issue, memory update, skill
change, or publication occurs without the user's explicit approval.
