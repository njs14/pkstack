## Reviewed adaptation

The port retains surface-specific design intent, preservation versus redesign, task-oriented
command selection, evidence-based review, and bounded visual refinement. Four local references
condense the source methods; they are adaptations, not an exact copy of every upstream playbook.
The user brief and accessibility requirements win over model-specific aesthetic bans. Native
Kiro planning remains authoritative; existing authorization and settled decisions replace
mandatory repeated interviews and confirmation rounds.

The binary launcher can download a release executable, the browser runtime injects live controls,
and the font index is over 1 MB. These assets are inventoried but excluded, along with hooks,
shortcut installation, upstream subagent prompts, decision-page machinery, and platform manuals.
PKStack ships no Impeccable detector and makes no claim that its 61-rule scan ran. `live`, hooks,
pin/unpin, and runtime doctor are unsupported; the wrapper explains that boundary. Normal design
work can use an already available project browser workflow without installing another runtime.
The existing detector bounds remain unchanged; upstream changes exceeding them require maintainer
review, including changes to the large excluded data blobs.

`shape`, `audit`, and `critique` preserve their non-editing scope. Product/design documentation is
written only when requested, using the project's existing authority. Skill creation remains in
`writing-for-agents`; `create-verification-skill` owns the specialized verifier case. Codex's
built-in skill creator is a host capability and is not a bundled Kiro dependency.
