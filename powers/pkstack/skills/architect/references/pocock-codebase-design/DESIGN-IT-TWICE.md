# Compare structurally different interfaces once

Frame the problem, real callers, constraints, dependency categories, and acceptance criteria
before proposing designs. Architect's existing arena owns this comparison. Produce at least two
structurally different usage-first scaffolds: for example a minimal cohesive operation versus an
explicit state-owning interface. Additional native Kiro subagents are optional bounded contributors,
not a required three-agent fanout. Reuse evidence and inherit the session's model and effort.

For each design show public types and operations, invariants and errors, caller examples, hidden
policy, adapters, test strategy, and tradeoffs. Compare interface depth, locality, seam placement,
and the user's criteria. Recommend one; retain parts of another only when they fit coherently.
Present design-only work conversationally or inside the active native Spec's permitted surface.
Implementation requires its existing authority; a comparison does not approve native phases.
