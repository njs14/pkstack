# Compare visual alternatives

Use the existing page or host surface when it gives realistic context. In a disposable local
prototype, keep shared data and navigation while varying rendering. Offer about three structurally
different alternatives with distinct layout, information hierarchy, or primary action; recoloring
the same layout is not another design. Use the project's styling system and Impeccable's methods.

A URL variant parameter and a small switcher can make alternatives easy to compare. Preserve
other query parameters and keyboard input behavior; never intercept typing in editable fields.
Show the selected variant and relevant state. Use stubs for any mutation and exclude prototype
controls from production. Check the actual rendered page at relevant viewport sizes.

Capture which design choices were useful and why. Implement the chosen behavior through the native
workflow with proportionate production proof; preserve or discard prototype artifacts only within
existing authority. Follow [the shared retention method](README.md).
